TankiTanguy

Un jeu de tanks multijoueur en réseau, en C++. Un serveur fait autorité sur la partie : les joueurs ne lui envoient que leurs touches, et il leur renvoie l'état du monde 60 fois par seconde. Tout passe par UDP, avec un protocole binaire écrit de zéro.

C++UDPWinsockMultithreadingClient / serveur
Équipe binôme avec Maël LemairePlateforme Windows

Connexion

Combat

Tanks pilotés aux flèches, tir à la barre d'espace. Un missile retire 50 points de vie sur 100.

Score

10 points par touche, affichés en haut de l'écran, avec la barre de vie en bas.

Réapparition

Après une destruction, le tank revient à une distance minimale des autres joueurs.

Protocole

Un en-tête de 17 octets

Tous les paquets commencent par le même en-tête, écrit champ par champ dans l'ordre réseau (big-endian) pour être lu correctement sur n'importe quelle machine.

ChampTailleRôle
protocolMagic2 octetsVaut 0xCAFE : un paquet qui ne commence pas par là est rejeté.
protocolVersion1 octetRefuse les paquets d'une version incompatible.
packetType1 octetUn des 12 types de message.
playerId1 octetLe joueur concerné, pour router le paquet côté serveur.
sequence2 octetsNuméro du paquet, utilisé pour écarter les snapshots arrivés en retard.
ack · ackBits2 + 4 octetsPrévus pour accuser réception des 32 derniers paquets.
timestampMs4 octetsHorodatage d'envoi.
Total17 octetsTaille fixe, suivie du contenu propre au type de message.

Écrire un float sur le réseau

Les valeurs sont converties dans l'ordre réseau avant l'envoi. Pour un float, on copie ses 32 bits dans un entier, puis on l'envoie comme un entier.

void WriteU32(uint32_t hostValue)
{
    hostValue = HostToNet32(hostValue);
    data.insert(data.end(), (uint8_t*)&hostValue,
                (uint8_t*)&hostValue + 4);
}

void WriteF32(float hostValue)
{
    static_assert(sizeof(float) == 4, "float is not 32 bits");
    uint32_t bits;
    std::memcpy(&bits, &hostValue, 4);
    WriteU32(bits);
}

Un thread dédié à l'écoute

Attendre un paquet bloque le thread qui attend. Le serveur et le client écoutent donc le réseau dans un thread séparé, pendant que la boucle principale continue de simuler et d'envoyer.

m_listenThread = CreateThread(NULL, 0, Listen, this, 0, NULL);

DWORD Server::Listen(LPVOID lpParam)
{
    while (pServer->m_running)
    {
        int ret = recvfrom(pServer->m_socket, ...);
        if (ret > 0)
        {
            PacketHeader header;
            if (!DeserializePacketHeader(reader, header))
                continue; // paquet inconnu : ignoré
            pServer->HandleOnPacketType(reader, header);
        }
    }
}

La boucle du serveur

À chaque tick d'environ 16 ms, le serveur fait avancer la partie, vérifie qui est encore là, puis envoie les événements et l'état du monde à tous les joueurs.

void Server::Update()
{
    m_pGM->ServerSideUpdate();   // applique les touches, simule
    CheckClientsConnected();     // timeout de 5 s
    SendNewMissile();
    SendMissilesToDestroy();
    SendServerSnapshotsToClients();
    Sleep(16);                   // environ 60 ticks par seconde
}
