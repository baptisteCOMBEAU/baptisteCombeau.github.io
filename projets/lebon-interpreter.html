LebonInterpreter

Lebon est un langage de programmation dont les mots-clés sont en créole réunionnais, et LebonInterpreter son interpréteur en C++. Un même programme peut s'exécuter de trois façons : en parcourant son arbre syntaxique, sur une machine virtuelle à registres, ou compilé à la volée en code machine x64.

Le langage

Programmer en créole

Lebon gère les nombres, les chaînes, les booléens, les variables, les conditions, les fonctions récursives et les closures. La plupart des mots-clés ont plusieurs synonymes : ran, rovoy, donn et ala veulent tous dire « retourner ».

Architecture

Du texte au code machine

Le code source passe par les mêmes étapes jusqu'à l'arbre syntaxique typé. Ensuite, trois moteurs d'exécution sont au choix, sélectionnés avec l'option --mode.

Lexer→ Parser→ AST→ Analyse sémantique→ Exécution
--mode=tree

Parcours d'arbre

L'interpréteur visite directement les nœuds de l'AST et évalue chaque expression. C'est le plus simple, et le plus lent.

--mode=vm

VM à registres

Le compilateur traduit l'AST en bytecode, exécuté par une machine virtuelle à registres.

--mode=jit

Compilation JIT

Un générateur de code parcourt l'AST et écrit directement des instructions x64 en mémoire exécutable, appelées ensuite comme une fonction native.

La machine virtuelle

Un bytecode sur 32 bits

Chaque instruction tient sur 32 bits : un opcode et trois opérandes de 8 bits, soit jusqu'à 256 registres par fonction. La VM compte 35 instructions, dont des variantes qui prennent directement une constante pour éviter un chargement de plus.

Des closures qui partagent leurs variables

Une fonction interne peut lire et modifier une variable de sa fonction parente. Le compilateur repère les variables capturées et les fait passer par des upvalues (GETUPVAL, SETUPVAL). Ici, ajoute modifie le total de compteur.

Mesures

Trois moteurs comparés

Le mode --bench exécute chaque programme plusieurs fois avec les trois moteurs. Sur Fibonacci, qui enchaîne les appels de fonction, la VM est 16,6 fois plus rapide que le parcours d'arbre, et le JIT 48,9 fois.

Outils

Un interpréteur qu'on peut inspecter

La ligne de commande permet d'afficher chaque étape et de mesurer le temps passé dans chacune. Une suite de tests couvre le lexer, le parser, l'analyse sémantique, le compilateur et la VM, avec les sorties attendues.

--mode=tree|vm|jitchoisit le moteur d'exécution
--dump-tokensaffiche les tokens
--dump-astaffiche l'arbre syntaxique typé
--dump-bytecodeaffiche le bytecode désassemblé
--tracetrace l'exécution
--timetemps passé dans chaque étape
--bench[=runs]compare les trois moteurs
--testlance la suite de tests
